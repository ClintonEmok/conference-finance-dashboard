## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight cell padding |
| sm | 8px | Inline spacing, chip gaps |
| md | 16px | Default form and card spacing |
| lg | 24px | Section padding, panel gutters |
| xl | 32px | Large content separation |
| 2xl | 48px | Major surface breaks |
| 3xl | 64px | Page-level separation |

Exceptions: 44px minimum hit target for icon-only controls, row actions, and sidebar trigger on touch; keep the visual box aligned to the 8pt system.

## Layout & Interaction

| Surface | Contract |
|---------|----------|
| Orders route | Event-scoped ledger only; remove the event selector dropdown. Keep the current filter, search, date-range, and export affordances. |
| Orders layout | Use a single dense ledger table on desktop. Each order shows canonical total, buyer/contact, status, and an inline attendee disclosure area directly beneath the order row. Attendees must never be hidden behind a separate detail page. |
| Attendee visibility | Show attendee payables inline as nested rows or an expanded subtable under each order. Keep the payable amount, attendee name, and provenance visible without extra navigation. |
| Reconciliation layout | Use a split-screen 50/50 workspace on desktop: unmatched payments on the left, outstanding orders on the right. Stack into one column on small screens, with payments first and orders second. |
| Reconciliation panels | Each panel is a table, not cards. Give each panel its own sticky header and its own scroll area for long lists. |
| Matching interaction | Selection is single-select per panel. When one payment and one order are selected, reveal a sticky bottom action bar with a primary "Match payment" button. |
| Match confirmation | Clicking the primary match action opens a confirmation dialog summarizing payment, order, matched amount, and the resulting allocation record. Confirming applies the allocation and removes both rows from the unmatched/outstanding lists. |
| Pagination | Use pagination controls for both ledgers instead of infinite scroll. Default page size is 25. |
| Loading | Use skeleton rows and skeleton summary tiles; never show empty chrome while data is loading. |
| Feedback | On success, show a positive toast and keep the selected event context visible. On failure, keep filters intact and surface a retryable error banner. |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#ffffff` / Dark `#0f0f14` | Page background, workspace canvas, table shells |
| Secondary (30%) | Light `#f6f5fb` / Dark `#1b1b24` | Cards, sidebar, sticky headers, panel surfaces |
| Accent (10%) | `#6b4eff` | Primary match CTA, selected rows, active filter chips, canonical total chips, focus rings |
| Destructive | `#dc2626` | Clear match, unmatch, discard allocation, destructive confirmation states |

Accent reserved for: selected rows, active filter pills, primary match/confirm actions, canonical money highlight chips, and focus states only.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Match payment |
| Empty state heading | No records match these filters |
| Empty state body | Clear filters or widen the date range to surface orders, payables, and unmatched payments. |
| Error state | Could not load canonical money data. Check your network and retry. |
| Destructive confirmation | Clear match: This removes the allocation record and returns the payment and order to the unmatched lists. Continue? |
