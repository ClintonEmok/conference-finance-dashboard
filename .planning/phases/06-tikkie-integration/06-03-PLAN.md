<objective>
Allow finance admins to configure reusable Tikkie payment templates per ticket type, so when they generate links for attendees, the amount and description are pre-filled based on the attendee's ticket type.
</objective>

<requirements>
- [ ] Store payment templates in database linked to event + ticket type (base defaults)
- [ ] Allow optional attendee-specific amount override stored on the attendee record
- [ ] Support description templates with {{name}} placeholder substitution
- [ ] Auto-match template when attendee's ticket type matches, but check for attendee override first
- [ ] Allow operator to override pre-filled values in the dialog
- [ ] Admin UI to manage templates per event
</requirements>

<steps>
  <step>
    <description>Add Prisma model for TikkiePaymentTemplate and attendee override field</description>
    <actions>
      - Add `TikkiePaymentTemplate` model with fields: id, eventId, ticketTypeLabel, amountMinor, descriptionTemplate, expiryDays, isActive, createdAt, updatedAt
      - Add unique index on (eventId, ticketTypeLabel)
      - Add relation to TicketTailorEvent
      - Add optional `tikkieAmountOverrideMinor` field to TicketTailorAttendee for per-attendee custom amounts
    </actions>
  </step>

  <step>
    <description>Create domain module for template operations</description>
    <actions>
      - Create `lib/domain/finance/tikkie-templates.ts`
      - Implement: createTemplate, updateTemplate, deleteTemplate, getTemplatesByEvent, matchTemplateForAttendee(attendee)
      - Template matching priority:
        1. Check if attendee has `tikkieAmountOverrideMinor` set → use that amount, fall back to template description
        2. Otherwise, find template where eventId matches AND ticketTypeLabel exactly matches attendee.ticketTypeLabel
        3. If no template found → no auto-fill (operator enters manually)
    </actions>
  </step>

  <step>
    <description>Create protected API routes for template management</description>
    <actions>
      - Create `app/api/dashboard/tikkie-templates/route.ts`
      - GET /api/dashboard/tikkie-templates?eventId=... - list templates for event
      - POST /api/dashboard/tikkie-templates - create template
      - PUT /api/dashboard/tikkie-templates/:id - update template
      - DELETE /api/dashboard/tikkie-templates/:id - soft delete (isActive = false)
    </actions>
  </step>

  <step>
    <description>Integrate template auto-fill into Tikkie dialog</description>
    <actions>
      - Modify `tikkie-link-dialog.tsx` to accept template defaults
      - Add logic: when opening dialog for attendee, call template matching API and pre-fill amount/description
      - Allow operator to override pre-filled values
    </actions>
  </step>

  <step>

      - Template status: "No template" → inline "Add" button, or shows amount/description → edit/delete

    </actions>
  </step>

<tech_considerations>
- User inputs amounts in euros; internally stored/converted to cents (amountMinor) for Tikkie API
- Two-level hierarchy: attendee override (priority 1) → ticket type template (priority 2) → manual entry
- Template matching uses exact ticketTypeLabel match - no fuzzy matching to avoid ambiguity
- Description template supports {{name}}, {{email}}, {{ticketType}} placeholders
- Templates are optional - dialog works without them (current behavior)
- One template per ticket type per event - update replaces existing
- Attendee override is stored on the attendee record for persistence across sessions
</tech_considerations>

<out_of_scope>
- Bulk generating links for all attendees of a ticket type (future feature)
- Integration with Ticket Tailor webhooks to auto-create templates
- Dynamic pricing based on custom answers
</out_of_scope>
