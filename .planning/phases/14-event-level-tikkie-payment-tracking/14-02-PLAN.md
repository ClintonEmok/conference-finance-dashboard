# Plan 14-02: Domain logic + API routes for event Tikkie + payment tracking

**Phase:** 14 — Event-Level Tikkie + Payment Tracking
**Depends on:** 14-01 (schema + Convex functions)
**Status:** Not started

## Context

With the schema and Convex functions from 13-01 in place, this plan builds the domain layer (business logic) and API routes that the UI will call. It also adds a payment sync job that fetches individual payments from the Tikkie API and stores them.

## Domain Logic

### 1. New file: `lib/domain/finance/tikkie-event-links.ts`

Event-level Tikkie link creation and management.

**`createEventTikkieLink(params)`** — params: `{ eventId: string, providerEventId: string, amountMinor?: number, description?: string, expiryDays?: number }`

- Validate inputs (same patterns as `tikkie-links.ts:340`)
- Check if event already has an event-level link via `api.tikkie.getEventPaymentLink`
- If exists, return it (don't create duplicate)
- Call `createPaymentRequest()` from `lib/integrations/tikkie/client.ts` with event-level description
- Store via `api.tikkie.createEventPaymentLink` mutation
- Return `{ link, created: boolean }`

**`getEventTikkieSummary(eventId)`** — returns event link + payment stats:

- Fetch event link via `api.tikkie.getEventPaymentLink`
- Fetch payments via `api.tikkie.getTikkiePaymentsByLink`
- Return `{ link, totalPayments, matchedPayments, unmatchedPayments, totalAmountMinor }`

Reuse from existing code:

- `normalizeProviderIdentifier()` from `tikkie-links.ts:245`
- `toTikkieDate()` from `tikkie-links.ts:315`
- `mapProviderStatus()` from `tikkie-links.ts:359`
- `createPaymentRequest()` from `lib/integrations/tikkie/client.ts:164`

### 2. New file: `lib/domain/finance/tikkie-event-payments.ts`

Payment ingestion and matching.

**`fetchAndStoreTikkiePayments(paymentLinkId, paymentRequestToken)`**

- Call `getPaymentRequestPayments(paymentRequestToken)` from `client.ts:184`
- For each payment in response, call `api.tikkie.upsertTikkiePayment` (idempotent by `paymentToken`)
- Map Tikkie payment fields to our schema (payerName, amountMinor, paidAt as epoch, etc.)
- Return `{ fetched, stored, skipped }`

**`syncAllEventPaymentLinks()`**

- Query all event-level links via `api.tikkie.getPaymentLinks` filtered by `linkType === "event"` (or all links and filter)
- For each, call `fetchAndStoreTikkiePayments`
- After fetch, run `api.tikkie.autoMatchTikkiePayments` for each event
- Return `{ linksScanned, paymentsFetched, paymentsNew, autoMatched }`

**`manuallyMatchTikkiePayment(paymentId, orderId)`**

- Call `api.tikkie.matchTikkiePayment`
- Return updated payment

Auto-matching strategy (reuses pattern from `convex/payments.ts:171-173`):

```typescript
// In the Convex mutation autoMatchTikkiePayments:
const matchingOrder = orders.find(
  (o) => o.buyerName?.toLowerCase() === payment.payerName.toLowerCase()
)
```

Single exact match → auto-assign. Multiple matches → leave as unmatched for manual resolution.

## API Routes

### 3. New file: `app/api/dashboard/tikkie-event-links/route.ts`

**`GET ?eventId=xxx`** — authenticated via `requireApiUser()`

- Returns event Tikkie link summary + payment list
- Response: `{ link, payments, stats }`

**`POST`** — create event-level Tikkie link

- Body: `{ eventId, providerEventId, amountMinor?, description?, expiryDays? }`
- Calls `createEventTikkieLink()`
- Returns 201 if created, 200 if already exists

**`PATCH`** — manual match a payment to an order

- Body: `{ paymentId, orderId }`
- Calls `manuallyMatchTikkiePayment()`
- Returns updated payment

Error handling: Same patterns as existing `app/api/dashboard/tikkie-links/route.ts` (TikkieApiError handling, auth guards, validation).

### 4. New file: `app/api/jobs/tikkie/event-payment-sync/route.ts`

**`POST`** — authenticated via `requireApiUser()`

- Calls `syncAllEventPaymentLinks()`
- Returns `{ ok, linksScanned, paymentsFetched, paymentsNew, autoMatched }`
- Meant to be called by a cron or manual trigger

### 5. Extend webhook: `app/api/webhooks/tikkie/route.ts`

When a webhook notification arrives for an event-level link:

- After existing `refreshTikkiePaymentLinkStatus` call
- If the link has `linkType === "event"`, also trigger `fetchAndStoreTikkiePayments` for that link

### 6. Convex hooks: `lib/convex/hooks/tikkie.ts`

Add:

- `useEventPaymentLink(eventId)` — wraps `api.tikkie.getEventPaymentLink`
- `useTikkiePaymentsByLink(paymentLinkId)` — wraps `api.tikkie.getTikkiePaymentsByLink`
- `useAutoMatchTikkiePayments()` — wraps `api.tikkie.autoMatchTikkiePayments`
