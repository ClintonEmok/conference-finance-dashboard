  <files>convex/signupSubmission.ts, lib/types/signup.ts</files>
  <read_first>convex/_generated/ai/guidelines.md, convex/schema.ts, convex/accommodation.ts, .planning/phases/18-dual-source-event-signup-platform/18-CONTEXT.md</read_first>
  <action>
    Create `convex/signupSubmission.ts` with a submission entrypoint named `submitSignupEnvelope` using strict validators.
    Use explicit canonical submission tables (additive schema updates if missing, no required `signup*` prefix):
    - `submissions` (header/booker-level data, booking ref, source, event linkage, notes, submitted timestamp).
    - `submissionAttendees` (one row per attendee with required rooming attributes; `submissionId` as `v.id("submissions")`).
    - `submissionTicketSelections` (one row per attendee-ticket selection, `quantity` fixed to `1`, `attendeeId` required to avoid mixed aggregate/per-attendee models).
    - `submissionAssignments` (optional attendee-to-slot assignment intent rows).
    - `submissionIdempotency` (idempotency key/fingerprint + submission id + expiration timestamp; do not store names/emails/phones here).
    Use typed Convex ids (`v.id(...)`) for table relationships where canonical ids are available (`eventId`, `submissionId`, `attendeeId`, `ticketTypeId`, `slotId`).
    Add indexes for operational reads:
    - `submissions`: `by_eventId`, `by_bookingRef`, `by_submittedAt`.
    - `submissionAttendees`: `by_submissionId`.
    - `submissionTicketSelections`: `by_submissionId`, `by_ticketTypeId`.
    - `submissionAssignments`: `by_submissionId`, `by_slotId`.
    - `submissionIdempotency`: `by_eventId_and_idempotencyKey`, `by_eventId_and_fingerprint`, `by_expiresAt`.
    Persist in a single mutation transaction:
    - Submission header: event id, source, idempotency key, honeypotSeen flag, notes.
    - Booker: name, email, phone.
    - Attendees array with required rooming details (`gender`, `location`, `dietaryRestrictions`, `roommatePreference`, `roommateAvoid`, `phone`).
    - Ticket selections array and assignment intent array (attendee-to-slot mapping where provided).
    Write child records only after all input validation passes. If any invariant fails, throw before writes that would leave partial state.
    Keep PII minimized: only persist contact fields required for booking/assignment execution, avoid duplicating contact fields across child tables when not needed.
    Extend `lib/types/signup.ts` with `SignupSubmissionEnvelope` and `SignupSubmissionResult` shared types (including `submissionId`, `bookingRef`, `submittedAt`).
  </action>

    - Submission-side tables include indexes `by_submissionId` for child lookups and `submissions.by_bookingRef` for restore lookups.
    - `submissionTicketSelections` model is unambiguous (per-attendee rows; `quantity = 1`; `attendeeId` required).
