# Phase 40 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Phase nature:** BACKEND finance phase. There are no new screens, routes, navigation, or layout changes. This contract governs how existing surfaces *display* the accommodation-inclusive canonical totals correctly, and nothing else.

---

## Phase UI Scope

**Hard rule (non-negotiable):** No UI surface computes money. Every amount rendered comes from canonical contracts — the extended `loadOrderAmountDueBreakdowns` loader, the pure domain module `lib/domain/finance/accommodation-amounts.ts`, and the server-derived payloads those feed. The UI renders provided values verbatim.

| Surface | Effect of Phase 40 |
|---------|--------------------|
| Public track-payment (`app/track-payment/page.tsx`, via `signupSubmission.getByBookingRef` + `publicTracking.getByBookingRef`) | **Only surface with a rendering change.** "Total" metric card now shows the accommodation-inclusive canonical amount-due (already reads `tracking.payment.totalDueMinor`). Digital Receipt gains optional accommodation line rows (base / superior upgrade / cot) when selections exist. Inline tickets-only total replaced server-side. |
| Order ledger (`components/dashboard/finance/legacy-orders-surface.tsx`, orders API) | No rendering change. Amount Due / Paid / Left columns and per-attendee rows automatically show accommodation-inclusive values because they read the canonical loader. |
| Reconciliation, reports, revenue, attendee detail, event overview | No rendering change. All consumers of `loadOrderAmountDueBreakdowns` / `getOrderWithAttendees` pick up accommodation-inclusive totals automatically. |
| Tikkie payment CTA (`components/signup/SuccessPage/TikkieSection.tsx`) | No rendering change. Link expected amount is sourced from canonical amount-due server-side; QR + "Open Tikkie" UI is untouched. |

**Out of scope (explicit):** new routes; new components; layout changes; admin "Upgrades & Options" tab (Phase 41); signup options step (Phase 42); permalink config-change edits (Phase 43); refund/donation re-price surfacing (Phase 43).

## Typography

Locked from existing surfaces — no new type roles.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 | 1.5 | Receipt secondary text, muted where existing |

## Color

Locked from `app/globals.css` and existing surfaces. 60/30/10 split.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `oklch(1 0 0)` (light) / `oklch(0.145 0.008 326)` (dark) | Page background |
| Secondary (30%) | `--card` white / `bg-card/40` glass, `--muted` `oklch(0.96 0.003 325.6)`, `--border` `oklch(0.922 0.005 325.62)` | Receipt cards, row backgrounds, borders |
| Accent (10%) | `--primary` `oklch(0.457 0.24 277.023)` | Interactive links/buttons, active states, metric/icon accents only |
| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` | Destructive actions only — none in this phase |
| Semantic money (existing) | paid `emerald-600`, outstanding `rose-600`, pending `amber-500/10` badge | Orders table — locked, unchanged |

Accent reserved for: primary buttons, link text ("Open details", order-id links), metric-card icons (`text-primary`), progress-bar fill. **Never** for money figures — money is `text-foreground` (values) / `text-muted-foreground` (metadata), or the locked emerald/rose semantics in tables.
