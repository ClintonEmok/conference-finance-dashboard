# Quick Task 260815-0g5: Redesign the Communications Center - Context

**Gathered:** 2026-08-15
**Status:** Ready for planning

<domain>
## Task Boundary

Redesign the Communications Center (`/dashboard/events/{slug}/communications`) from a stacked-card page into a two-column composer with a live announcement email preview, plus audience drill-down, master-detail broadcast tracking, draft autosave, and saved announcement templates.

User pain points (all selected): layout/visual design, can't preview the email, audience tools weak, workflow fragmented, info/status clarity, missing features.

</domain>

<decisions>
## Implementation Decisions

### Layout
- Two-column composer: left rail = compose + audience filters + send; right = sticky, debounced live email preview rendered from the real `AnnouncementEmail` template in an `iframe srcDoc`. Broadcasts/tracking below the fold.

### Email preview
- Use `render()` from `@react-email/render` (already a dependency, v2.0.4) client-side to render `lib/email/templates/announcement.tsx` with the live compose values, injected into an iframe via `srcDoc`. Debounce ~300ms. Placeholder manage-booking (`${origin}/booking/BK-EXAMPLE/manage`) and signup (`${origin}/signup/{slug}`) URLs. Announcement template only — SignupConfirmationEmail is transactional, not broadcastable.

### Audience tools
- Raise the `previewAudience` query limit from 100 to 200 (backend caps at 200). Add client-side search by name/email/ref and chunked reveal-all (25 → 200) instead of the hard 25-row cut. Fix `describeFilters` to resolve the raw ticket `Id` to its human label in the confirm dialog.

### Workflow
- Merge test-send + broadcast into the compose flow. Keep explicit confirmation dialog ("Confirm broadcast") with a human-readable filter summary. Preserve invariants: `scheduleEmailBroadcast` with `authorize: true`, no `window.confirm`, no `setInterval`, async delivery.

### Status clarity
- Merge `ActiveBroadcastCard` + `HistoryCard` into one master-detail `broadcasts-panel.tsx`: history list (status badge, timestamp, recipient count) + detail pane (progress bar, sent/failed/pending, created/completed timestamps, stored filter summary, recipient table filterable by status). Use human-readable broadcast status labels.

### Draft autosave
- localStorage-backed compose state keyed by event id; debounced write; restore on mount; discard-draft affordance. New `lib/dashboard/communications/drafts.ts`.

### Saved templates
- New Convex table `emailTemplates` (eventId, name, title, message, eventName, eventDate, eventLocation, paymentUrl?, nightBeforeNote?, createdAt, updatedAt) + `by_eventId` index. New `convex/emailTemplates.ts`: `getTemplatesForEvent` (operator-auth query), `saveTemplate` (upsert by id), `deleteTemplate`. UI: template picker + "Save as template" in the compose panel. Announcement-only (no new broadcast template types).

### the agent's Discretion
Component breakdown, exact styling, and file organization are at the agent's discretion following the existing dashboard conventions (WorkspaceFrame, Card, shadcn/ui components, existing `components/dashboard/communications/` patterns).

</decisions>
