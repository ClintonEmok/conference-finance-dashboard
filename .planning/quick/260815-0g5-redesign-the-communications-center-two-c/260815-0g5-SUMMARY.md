# Decisions
- Two-column composer: left rail = compose fields, template picker/save-as/discard-template, all five audience filters, search + chunked reveal (25 → 200), test-send, explicit Confirm broadcast; right rail = sticky live preview. Broadcasts panel rendered below the fold.
- Live preview renders the real AnnouncementEmail via @react-email/render client-side into an iframe srcDoc, debounced ~300ms with a monotonic sequence ref so only the latest render result is applied (stale-render protection). Placeholder URLs use ${origin}/booking/BK-EXAMPLE/manage and ${origin}/signup/{slug}. No hand-built preview, no window.confirm, no setInterval.
- Audience: previewAudience default now returns up to 200 (was 100); hard cap stays Math.min(..., 200). Client-side search across name/email/booking reference; rows reveal in chunks of 25 until all returned rows are visible; search/reveal reset whenever filters change. describeFilters resolves the raw ticket type ID to its human label in the confirm dialog and in the stored-filter summary.
- Drafts: compose state autosaves to localStorage under an event-scoped key (debounced 500ms), restored on mount, discardable — all helpers SSR-safe. Drafts are announce-only.
- Saved templates: new emailTemplates table + API. getTemplatesForEvent is bounded (take 100) and newest-first (updatedAt desc). saveTemplate inserts without an ID and patches in place with an ID, rejecting cross-event IDs; deleteTemplate verifies event ownership and deletes only the requested row. Every function requireIdentity-gated.
- Broadcast tracking merged into one master-detail panel: status-filterable history list (human-readable labels, timestamp, recipient count), selected-broadcast detail (progress bar, sent/failed/pending, created/started/completed/cancelled timestamps, stored filter summary), recipient table filterable by status (server-side via getBroadcastRecipients status arg). Initial history item auto-selected on load; reactive useQuery only — no polling. scheduleEmailBroadcast still called with authorize: true; async scheduler delivery contract untouched.
- The four broadcast queries stay wired: previewAudience + getBroadcastHistory in the workspace, getBroadcastById + getBroadcastRecipients in broadcasts-panel.
