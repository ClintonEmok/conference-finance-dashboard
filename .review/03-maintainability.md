# v6.0 Production-Readiness Maintainability Review

## Summary

The change set contains several maintainability hazards around deployment safety, runtime configuration, preview data provenance, and stale operator-facing contracts. The most serious issue is that the code comments describe the backfill/seed as preview-only while the runbook explicitly documents a production invocation, and the guard permits that invocation (or skips the deployment check when `CONVEX_SITE_URL` is absent). Email and token configuration also has multiple runtime-specific fallbacks that can silently produce localhost links or leave the intended gate in degraded mode.

## Documentation drift

- The legacy operator note says a production-like URL “fails closed” and prohibits production, while the production runbook says `preview: true` plus the production URL is the intended production backfill command. The code implements the latter whenever `CONVEX_SITE_URL` is available, and implements an even weaker guard when it is absent.
- The environment inventory says `RESEND_FROM_NAME`/`RESEND_FROM_EMAIL` and `NEXT_PUBLIC_SITE_URL` are Next-server/build settings, but the email actions and templates execute/read them in the Convex runtime. It also omits the `NEXT_PUBLIC_APP_URL` value used to build booking links.
- The preview note documents sanitizer + `npx convex import`; the v6 runbook documents the seed mutation. The seed imports a fixture from `tests/fixtures`, so the stated sanitizer provenance is not the path actually exercised by the runbook.
- All rehearsal documentation treats 72 as an unconditional expected count. It does not handle the known 71-vs-72 discrepancy or define which count is authoritative for a rehearsal versus the audited fixture.
